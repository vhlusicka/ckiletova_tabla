# Čkiletova tabla — Regression Test Specification

This specification focuses on primary user journeys and recurring regression coverage. Button names, labels, and entered values are quoted exactly so the scenarios can be translated into Appium actions. The **Automated** column is intentionally blank as it will be populated upon implementing test automation.

## Feature 2 — League stage

| Test case ID | Test case TITLE | Type of test | Steps written in Gherkin syntax | App version | Automated |
|---|---|---|---|---|---|
| CT-02-001 | Record a league match result | Smoke | **Given** a league-only tournament with contestants "Ana", "Bruno", "Carla", and "David" and "2" matches per contestant is active<br>**When** the user taps the button with text "PLAY GAME 1  ›"<br>**Then** the labels "HOME", "VS", and "AWAY" are displayed<br>**When** the user enters "2" in the HOME score field<br>**And** the user enters "1" in the AWAY score field<br>**And** the user taps the button "FINISH MATCH"<br>**Then** a confirmation popup displays the score "2 – 1"<br>**When** the user taps the popup button "Confirm"<br>**Then** the heading "League table" is displayed<br>**And** the text "1 league games played" is displayed | 1.1.4 | Yes |
| CT-02-002 | Calculate league standings correctly | Smoke | **Given** an active league tournament is displayed before its first match<br>**When** the user taps the button "PLAY GAME 1  ›"<br>**And** the user enters "2" in the HOME score field<br>**And** the user enters "1" in the AWAY score field<br>**And** the user taps the button "FINISH MATCH"<br>**And** the user taps the popup button "Confirm"<br>**Then** the HOME contestant's row displays "3" under "PT", "1" under "P", and "1" under "W"<br>**And** the AWAY contestant's row displays "0" under "PT", "1" under "P", and "1" under "L"<br>**When** the user taps the button "PLAY GAME 2  ›"<br>**And** the user enters "1" in both score fields<br>**And** the user taps the button "FINISH MATCH"<br>**And** the user taps the popup button "Confirm"<br>**Then** both contestants from game 2 have their "P" and "D" values increased by one<br>**And** both contestants from game 2 have their "PT" values increased by one | 1.1.4 | Yes |
| CT-02-003 | Schedule contestants without excessive waiting | Regression | **Given** a league tournament with contestants "Ana", "Bruno", "Carla", "David", "Eva", and "Filip" is active<br>**When** the user taps "PLAY GAME 1  ›" and stores both displayed contestant names<br>**And** the user enters "1" and "0" in the score fields<br>**And** the user taps "FINISH MATCH" and taps the popup button "Confirm"<br>**And** the user taps "PLAY GAME 2  ›" and stores both displayed contestant names<br>**And** the user enters "1" and "0" in the score fields<br>**And** the user taps "FINISH MATCH" and taps the popup button "Confirm"<br>**And** the user taps "PLAY GAME 3  ›" and stores both displayed contestant names<br>**Then** all six contestant names appear exactly once across the stored names from games 1, 2, and 3 | 1.1.4 | Yes |

| CT-02-008 | Persist an active tournament after reopening the app | Regression | **Given** an active league tournament contains the confirmed result "2 – 1"<br>**When** the user closes the application<br>**And** the user launches "Čkiletova tabla" again<br>**Then** the heading "League table" is displayed<br>**And** the text "1 league games played" is displayed<br>**When** the user taps the button "All matches"<br>**Then** the result "2 – 1" is displayed<br>**When** the user taps the button "‹  Back to table" and then taps the next "PLAY GAME" button<br>**Then** the same next fixture scheduled before closing is displayed | 1.1.4 | Yes |
